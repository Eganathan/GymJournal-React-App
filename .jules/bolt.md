## 2025-03-09 - [Batching Zustand Store Actions to Prevent Redundant Network Calls]
**Learning:** Sequential network updates tied to Zustand store actions can trigger N network calls for refreshing data after individual writes. For instance, looping over `.updateEntry` calls that inherently invalidate and refetch the same 'snapshot' endpoint leads to massive redundancy (O(N) data refetches).
**Action:** Parallelize iterative write calls via `Promise.all` and decouple the subsequent 'store refresh/refetch' action from the individual write methods using an options flag (e.g. `{ skipSnapshotRefresh: true }`). Then manually trigger a single store data refresh after all Promises resolve. This converts N write requests + N refetch requests into N concurrent write requests + 1 refetch request.
