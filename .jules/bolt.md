## 2024-05-24 - Timer-driven Re-renders and Derived Computations
**Learning:** Components with active timers (like `WorkoutActive.js` which updates elapsed time every second) trigger frequent re-renders of their entire sub-component tree. If child components perform derived computations (like reducing personal bests to find a 1RM) inline, these computations will execute pointlessly on every tick.
**Action:** Always memoize derived computations with `useMemo` in components that are subject to frequent, timer-driven re-renders (or their children) to prevent redundant calculations and preserve UI performance.
## 2024-05-24 - Batching API Calls and Snapshot Refresh
**Learning:** Sequential `await` calls in loops (e.g., `for (const u of updates) await updateEntry(...)`) create a performance bottleneck, changing total I/O time from O(1) to O(N). When batching these requests using `Promise.allSettled`, individual state updates (like `updateEntry` or `logEntries` in `metricsStore.js`) may trigger their own redundant background refreshes (e.g., `fetchSnapshot(true)`).
**Action:** Replace sequential `await` loops with `Promise.allSettled` to execute them concurrently. Furthermore, pass an option (like `{ skipSnapshotRefresh: true }`) to the individual store methods to prevent them from firing multiple redundant background data refreshes concurrently, and then call a single `refreshSnapshot()` once all promises resolve.
