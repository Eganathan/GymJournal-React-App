## 2025-03-09 - Parallelizing Zustand API Calls and Avoiding Redundant Refresh Requests
**Learning:** When making sequential asynchronous API calls within a loop (e.g., updating multiple logged entries), iterating over an array and `await`ing each request sequentially results in O(N) wait times relative to the number of requests. Furthermore, if each action in the Zustand store triggers a network request to refresh the overall application state (e.g., `fetchSnapshot`), running these actions concurrently using `Promise.all` triggers N redundant state refresh network requests.
**Action:** Replace `for...of` loops involving sequential `await`s with `Promise.all` for a performance enhancement. Add an `options = { skipSnapshotRefresh }` parameter to Zustand actions to conditionally suppress automatic state refresh queries, and explicitly call the refresh function just once after `Promise.all` resolves successfully.
