## 2023-10-27 - Batch API Updates Optimization in Metrics Log
**Learning:** Sequential `await` calls in a loop (like updating multiple metrics in `MetricsLog.js`) are O(N) operations and block subsequent executions unnecessarily. In this app architecture, individual store API updates automatically triggered separate full snapshot refreshes from the server, multiplying both the network requests and latency.
**Action:** Always batch concurrent, independent API updates using `Promise.all`. For state stores (like Zustand in `metricsStore.js`), decouple side-effects (like state refreshes) from the individual update actions by introducing an `options = { skipSnapshotRefresh: true }` parameter, allowing the consuming component to trigger a single manual `refreshSnapshot()` once all updates complete. This changes the O(N) API calls and O(N) state refreshes into a single concurrent O(1) batch + 1 refresh.
