## 2024-05-18 - Replacing Sequential Store I/O with Promise.all
**Learning:** In Zustant state stores that integrate API calls (e.g., `metricsStore.js`), executing multiple individual update functions sequentially in a React component loop can cause massive N+1 query and unnecessary repetitive UI re-renders if the store action automatically triggers a full state refresh upon success.
**Action:** When designing batch update operations in components, extract the individual update methods to return Promises, pass an option (`skipSnapshotRefresh: true`) to defer internal state refreshes, use `Promise.all` for parallel execution, and execute a manual state refresh at the end. Make sure to keep the changes backwards compatible so existing implementations without the option continue working normally.
