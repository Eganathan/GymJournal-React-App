## 2024-05-18 - [Optimizing MetricsLog Updates]
**Learning:** In applications using Zustand and a REST API, executing multiple state-mutating API calls in sequence (e.g., PUT requests in a `for` loop) can severely degrade performance if each call independently invalidates a store's cache and triggers a new refetch. This causes N PUT requests to result in N redundant GET requests, leading to network bottlenecks.
**Action:** When saving batch updates (e.g., the `handleSave` function in `MetricsLog.js`), use `Promise.all` to execute the updates concurrently. Extend the Zustand store methods (`updateEntry`, `logEntries`) to accept an `options = { skipSnapshotRefresh: true }` parameter to suppress independent cache invalidation, and manually trigger a single cache invalidation (`refreshSnapshot()`) after all promises resolve.
