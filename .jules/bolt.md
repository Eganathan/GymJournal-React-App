## 2025-03-09 - Parallelize API calls using Promise.all
**Learning:** Sequential await calls in loops (e.g. `for...of` loops) block each other and cause I/O time to scale as O(N). Parallelizing them with `Promise.all` improves performance to O(1) total I/O time. However, when those individual API methods automatically trigger state cache invalidations and refreshes on success (e.g., updating a full snapshot after every log/update), parallelizing them can lead to multiple redundant concurrent requests to fetch the same snapshot.
**Action:** When converting sequential API calls to parallel `Promise.all`, ensure underlying store methods support options (e.g. `opts.skipSnapshotRefresh`) to skip automatic side-effects like fetching snapshots. Then, manually invalidate and trigger the refresh exactly once after the `Promise.all` resolves.
